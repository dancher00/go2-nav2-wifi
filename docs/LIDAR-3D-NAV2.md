# Go2: Point-LIO, RViz и Nav2

Текущее состояние закреплено 11 сентября 2026 после отката эксперимента
со сглаживанием позы. Point-LIO работает на Jetson, RViz и Nav2 — на ноутбуке.

## Запуск

Просмотр SLAM и карты препятствий без управления движением:

```bash
GO2_RECORD=1 ./mapping.sh --3d --plan
```

Экспериментальная навигация по цели, после подъёма робота пультом:

```bash
GO2_RECORD=1 ./mapping.sh --3d --nav
```

В режиме `--nav` onboard sport bridge переключает управление на velocity walk.
Цель задаётся инструментом **2D Goal Pose**. Панель **Go2 Speed** задаёт предел
линейной скорости 0.10–0.60 м/с; начальное значение — 0.30 м/с. Отпустите
ползунок или нажмите **Apply**. Подтверждение **Nav2: limit … m/s** означает,
что контроллер принял параметры. Угловой предел — 0.35 рад/с.

Закрытие RViz или Ctrl+C завершает принадлежащую запуску сессию. Результаты
переносятся с Jetson в `ws/maps/lidar3d/` после проверки контрольных сумм.
`GO2_RECORD=1` дополнительно сохраняет входные данные для диагностики.
Существующая карта не используется для локализации при новом запуске.

## Действующая конфигурация

- Point-LIO: выходная модель с гироскопом, `lidar_meas_cov=0.01`,
  `imu_meas_omg_cov=0.1`. Ускорения исключаются только внутри backend.
  Экспериментальные параметры для уменьшения колебаний отменены.
- Поза корпуса и суставов имеет согласованные временные метки. TF корпуса
  публикуется без дополнительного сглаживания (`smooth_alpha=1.0`).
- Фильтр URDF удаляет точки внутри отдельных звеньев и близкие возвраты,
  лучи к которым перекрыты звеньями. Nav2 получает `/lidar3d/obstacle_points`.
  Исходное облако SLAM остаётся неизменным. Подробности:
  [URDF-SELF-FILTER.md](URDF-SELF-FILTER.md).
- В `--plan`: SmacPlanner2D, rolling costmap 30×30 м, разрешение 0.1 м,
  радиус 0.22 м. Этот профиль предназначен только для просмотра планов.
- В `--nav`: SmacPlannerLattice, разрешение 0.05 м, ориентированный footprint
  Go2 81×40 см с padding 3 см. Локальная карта 6×6 м. Размеры и проверка:
  [GO2-FOOTPRINT.md](GO2-FOOTPRINT.md).
- Контроллер: DWB с RotationShimController; время проверки продвижения 35 с.
  Прямой разворот с обходом проверки столкновений отключён.
- RViz: английский интерфейс, красная траектория толщиной 2 см, окно последних
  сканов 10 с в профилях planning/navigation, частота отрисовки 10 FPS.
  Передача облака ограничена интервалом 0.1 с, фактически около 7.7 Гц.

При необходимости сборка панели: `bash /ws/scripts/build-rviz-controls.sh`
внутри контейнера. `mapping.sh --3d --nav` собирает отсутствующий плагин.

## Проверено и ограничения

Были успешные физические проходы к отдельным целям, включая проход за
17.3 с в `mapping.4YfiVB`. Надёжность возвращения к точке позади робота
после добавления Rotation Shim не подтверждена. Неизвестные клетки разрешены
для глобального планирования в `--nav`, но не означают проверенно свободное
пространство. Нового испытания движения после последнего отката не было.

Порог препятствий 0.15–1.6 м задан относительно начальной системы карты.
При ошибке выравнивания или дрейфе SLAM пол может попасть выше порога и
стать препятствием. Адаптивный фильтр плоскости пола не внедрён. Эксперимент
со сглаживанием не решил эту проблему и был полностью отменён.

Point-LIO здесь не имеет loop closure. Работа на уклонах, ступенях,
перепадах и под нависающими препятствиями не подтверждена. Измерения
стационарной позы не доказывают точность карты при ходьбе.

На роботе наблюдались отключения USB Wi-Fi адаптера Realtek с последующим
переподключением. Они прерывают поступление данных в RViz. Это отдельная
неустранённая причина зависаний. Расхождение системных часов также не
устранено системной настройкой; суставы согласованы с временем позы локально.

Исторические измерения находятся в `docs/measurements/`. Прежний фильтр
одиночных низких выбросов заменён URDF-фильтром и больше не используется.
