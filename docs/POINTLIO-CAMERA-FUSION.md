# Point-LIO + штатная камера Go2

Ветка `experiment/pointlio-camera-fusion` объединяет проверенный Point-LIO
(база `22a1b91`) и адаптер штатной камеры. Все вычисления выполняются на Jetson;
ноутбук запускает только RViz. Команд движения здесь нет.

## Что работает

Измеренные точки `/camera_fusion/lio/registered` накапливаются в ограниченной
карте с вокселем 5 см (до 200 000 точек). Цвет берётся из штатной камеры,
после исправления дисторсии и проекции через интерполированную позу Point-LIO.
Цвет не меняет координаты измеренных точек. Геометрия добавляется независимо
от наличия изображения и разрешения на окраску. Неокрашенные точки серые.

Это окрашивание LiDAR-карты, а не объединение двух независимых траекторий.
Loop closure и исправление дрейфа здесь не добавлены. Результат возврата около
3 см относится к одному прежнему тесту базового Point-LIO, не к этой ветке.

## Запуск

Нужны уже подготовленные на Jetson образы `go2-legkilo:local` и
`go2-stock-camera:local`, SDK камеры и образ `go2-humble:local` на ноутбуке.
Это пока workflow для имеющейся установки, не установка на чистый Jetson.

```bash
export GO2_SSH_CONTROL_PATH=/tmp/go2-fusion-ssh  # если этот SSH master открыт
bash fusion-mapping.sh start-preview
bash fusion-mapping.sh rviz
# В другом терминале:
bash fusion-mapping.sh status
bash fusion-mapping.sh save
bash fusion-mapping.sh stop
```

`start-preview` создаёт отдельный `go2-camera-pointlio`, затем
`go2-camera-fusion`. Существующий `go2-lidar3d-onboard` не изменяется.
Не запускайте второй Point-LIO без необходимости, если первый уже нагружает
Jetson: для подключения к работающему backend есть `camera-fusion.sh`.
Его конфигурация по умолчанию читает `/lidar3d/odom` и `/lidar3d/registered`.
`GO2_FUSION_CALIBRATION` задаёт свой JSON с frame/topic/extrinsic/intrinsic.
`restart-preview` перезапускает только окраску, сохраняя текущую сессию Point-LIO.
`stop` сохраняет данные и останавливает два контейнера этой ветки; камера
остаётся запущенной (управляется отдельно `stock-camera.sh`).

Изолированный backend использует исходные параметры Point-LIO, меняя только
входные/выходные топики и имя мировой системы координат. SHA патча backend
проверяется перед запуском. Потребитель прекращает работу при смене источника
одометрии или неоднозначности нескольких publishers. После перезапуска
backend нужна новая сессия окраски.

## Ограничение калибровки

Текущий профиль **не откалиброван для метрически точного слияния**. Intrinsics
взяты из стороннего SDK (720p с масштабированием до 1080p), положение камеры —
из URDF, LiDAR/body — из прежней оценки. Это исходное приближение, не результат
совместной калибровки. JPEG имеет timestamp получения, а не экспозиции.

Поэтому preview обновляет цвет только при малом движении по окну поз за 0.6 с
(диаметр поз / длительность: <0.05 м/с и <0.12 рад/с). Это фильтр против
ошибок задержки, не доказательство неподвижности. При движении геометрия
продолжает обновляться. В RViz показаны ограничение и состояние окраски.

`camera-fusion.sh start` и `start-da3` требуют `calibration_verified=true`
и `timing_verified=true`. Нельзя просто переключить флаги для обхода проверки:
нужно измерить intrinsics, camera/LiDAR extrinsics и задержку, затем проверить
проекцию на разных расстояниях и во время поворота.

## DA3

Подготовлен опциональный путь глубины через имеющийся TensorRT engine DA3 Small.
Позу и масштаб мира задаёт Point-LIO. Масштаб глубины оценивается по LiDAR,
проверяется на отдельных пространственных участках изображения. Новые точки
допускаются только рядом с подтверждением лидара и публикуются отдельно в
`/camera_fusion/da3_supported`. Это не заполнение невидимых областей.

**В текущем live-тесте DA3 выключена.** Полный путь DA3 + камера + LiDAR
после калибровки ещё требует проверки на роботе.

## Сохранение и проверка

Jetson: `~/go2-pointlio-camera-fusion/data/<session>/session/` содержит
`snapshot-*.ply`, NPZ с маской окрашенных точек, JSON состояния и копию
калибровки. При остановке пишутся `colored_map.ply`, NPZ и summary.
Первые 30 окрашенных кадров и соответствующие точки/позы сохраняются для
разбора проекции. Point-LIO сохраняет отдельную сессию в
`~/go2-pointlio-camera-fusion/pointlio/<session>/`.

Live-проверка 2026-09-10: робот лежал неподвижно. После исправления проверки
покоя обработано 37 из 43 изображений, накоплено 51 160 точек, 4 190 окрашены;
PLY/NPZ/JSON снимка созданы. Jetson видел подписку RViz на цветную карту через
Wi-Fi. Пример памяти: Point-LIO 326 MiB, окраска 140 MiB, камера 193 MiB.
Это проверка потока данных, а не точности цвета или качества карты при ходьбе.

```bash
python3 -m unittest discover -s tests -p test_camera_fusion.py
```

Семь проверок: интерполяция без экстраполяции, движение/шум поз, обратная
проекция и окклюзия, неизменность/ограничение геометрии, накопление без цвета,
независимая проверка масштаба DA3 и отбраковка некорректной матрицы камеры.
