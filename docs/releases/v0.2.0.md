# v0.2.0 — onboard 3D mapping and synchronized demo

This release adds the Jetson Point-LIO workflow to the existing Wi-Fi 2D
SLAM + Nav2 stack. The default `./mapping.sh` command remains the 2D workflow;
`GO2_RECORD=1 ./mapping.sh --3d` runs sensor-only 3D mapping with RViz on the laptop.

## Changes

- Corrected the camera/RViz demo alignment. The map is visible from the first
  frame; the video no longer starts with robot motion against a loading screen.
  The 37-second MP4 and preview are included in the repository and release assets.
- Added the 3D installation and verification guide, onboard Point-LIO setup,
  recorded-input replay and SHA256-verified map/trajectory transfer.
- Increased the Point-LIO initialization seed to 20,000 points, retaining the
  documented September 12 startup-validation results.
- Added URDF body and leg filtering, sensor/body pose composition, synchronized
  joint stamps and supervised 3D Nav2 planning/controller tools.
- Preserved the existing two-speed RViz panel changes: atomic linear/angular
  limits, acknowledgement and rejection reporting. Initial limits are 0.30 m/s
  and 0.70 rad/s; selectable maxima are 1.20 m/s and 1.50 rad/s.
- Fixed live 2D localization using simulation time and made closing RViz end
  the `--view` launch.
- Corrected test discovery to include pytest functions as well as unittest
  classes. CI also builds/tests the RViz panel and pins Unitree message sources.
- Aligned `go2_nav2` Python and ROS package metadata at 0.2.0.

## Upgrade

Follow [3D-QUICKSTART.md](../3D-QUICKSTART.md), setting current robot/laptop IPs
before running `./setup-lidar3d.sh --laptop` and `./setup-lidar3d.sh --jetson`.
Rebuild existing images: older local 3D images can lack SciPy or Unitree messages
even when they have the same `go2-lidar3d:local` tag. Restart the session to load
the updated configuration, motion bridge and RViz panel.

Keep the robot stationary until the first map appears. Normal 3D mapping sends
no motion commands; the operator drives with the handheld remote.

## Validation and limits

The September 27 audit passed 130 Python tests, built all three project packages
and passed the C++/Qt RViz speed-panel integration test in an isolated Docker
container without robot network access. The demo was decoded and visually
checked at the opening, through turns and at the final map view.

No new robot walking or navigation trial was performed for this release.
Historical live measurements are linked from the quick start. Point-LIO has
no loop closure in this profile. Persistent 3D map relocalization and navigation
after restart remain incomplete; the saved-map helper modules do not provide
an integrated launcher for that scenario. Leg-KILO, Point-LIO leg observations,
slopes and extended routes remain experimental. See the
[audit](../REPOSITORY-AUDIT-2026-09-27.md) and
[navigation acceptance record](../NAVIGATION-ACCEPTANCE-2026-09-12.md).
